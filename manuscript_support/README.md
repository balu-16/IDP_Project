# Manuscript tools and supporting evidence

`new_paper/` is a standalone LaTeX upload folder: main source, conference class, current PDF, short README, and `includes/*.tex`. This support folder is **not needed by Overleaf**.

## Layout

- `build_manuscript.py`: compile/check the paper, update the reviewer response, and create `latex_source.zip` here. Logs/intermediate files go to `build/manuscript_verified/`.
- `export_verified_results.py`: read completed experiment artifacts and regenerate only `.tex` fragments in `new_paper/includes/`; JSON/CSV evidence goes to `records/`.
- `paper_sources.json`: central mapping for SciFact/NFCorpus full protected-prefix tests and the older 648-query FiQA base test.
- `resource_integration.py`: read-only verification/import of the separate sealed constrained-oracle study.
- `records/`: numerical evidence, provenance, complete controls CSV, publication checks, visual inspection, and the cleanup audit. `before_cleanup.json` retains the pre-relocation evidence/checks.
- `reviewer_response.md`, `reproducibility_report.md`, `REVISION_STATUS.md`, and `RESUME.md`: current research and manuscript documentation.
- `latex_source.zip`: portable LaTeX upload archive, regenerated by each successful build. It contains no Python, JSON, or research datasets.
- `history.zip`: checksum-verified snapshot of the original `new_paper/` folder, including obsolete scripts, notes, figures, and tables. Original project-relative paths are retained. Extract into a temporary directory for inspection, not over the active project.

The manuscript uses **L6-guided GAS** consistently. Its note discloses protected-prefix refinement on SciFact/NFCorpus and the earlier FiQA configuration. FiQA's 100-query training confirmation is excluded.

## Verify and build

From the repository root, using the existing backend environment:

```bash
PYTHONDONTWRITEBYTECODE=1 backend/.venv/bin/python manuscript_support/build_manuscript.py
```

This compiles existing LaTeX only and checks provenance, source inputs, eight-page compliance, embedded fonts, references, overflow, and the mathematical statements. It creates no benchmark rankings or neural inference. The current PDF is copied to `new_paper/main.pdf`; administrative records stay here.

Regenerate results from **existing completed rankings**, then build:

```bash
PYTHONDONTWRITEBYTECODE=1 backend/.venv/bin/python manuscript_support/build_manuscript.py --export --check-metrics
```

`--check-metrics` independently checks saved rankings through NIST `trec_eval`. It does not retrieve candidates, run selectors, encode a corpus, or collect a dataset. Re-run only when updating results or when an evidence check is necessary.

For a read-only provenance and stored-ranking audit:

```bash
PYTHONDONTWRITEBYTECODE=1 backend/.venv/bin/python manuscript_support/export_verified_results.py --check
```

The exporter verifies complete test-query, method, seed, source/dependency, model, and artifact coverage; independently recomputes saved metric summaries and timing aggregates; and refuses incompatible inputs. It rejects confirmation or development directories as full-test sources. Experimental code, caches, and sealed runs are not modified.

4. Inspect the new PDF. Rebuilding refreshes publication checks; the previous visual inspection is historical evidence, not automatic approval of a changed PDF.
